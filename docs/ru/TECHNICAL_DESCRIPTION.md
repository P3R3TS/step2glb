# Техническое описание

## step2glb — Преобразователь STEP/IGES в GLB

---

**Версия документа:** 1.0  
**Дата:** Сентябрь 2026  
**Нормативные документы:** ГОСТ 19.201-78, ГОСТ 19.701-90  

---

## 1. Архитектура программы

### 1.1. Общая схема

Программа построена по архитектуре «GUI + Worker Process». Основной поток управляет графическим интерфейсом, а конвертация выполняется в отдельном процессе через `multiprocessing.Process`. Связь между процессами осуществляется через `multiprocessing.Queue`.

```
┌──────────────────────────────────────────────┐
│                  GUI (главный процесс)        │
│                                               │
│  ┌─────────┐  ┌──────────┐  ┌─────────────┐ │
│  │  Ввод    │  │ Настройки│  │   Вывод     │ │
│  └────┬────┘  └────┬─────┘  └──────┬──────┘ │
│       │            │               │         │
│       └────────────┼───────────────┘         │
│                    │                          │
│           ┌────────▼────────┐                │
│           │ Кнопка конверт. │                │
│           └────────┬────────┘                │
│                    │                          │
│     ┌──────────────▼──────────────┐          │
│     │  Очередь (опрос @100 мс)   │          │
│     └──────────────┬──────────────┘          │
│                    │                          │
│  ┌─────────────────▼─────────────────────┐  │
│  │  Прогресс  │  Статус  │  Лог         │  │
│  └────────────────────────────────────────┘  │
└──────────────────────────────────────────────┘
                      │
              Очередь (IPC)
                      │
┌─────────────────────▼────────────────────────┐
│          Рабочий процесс (daemon)             │
│                                               │
│  ┌──────────────────────────────────────┐   │
│  │  1. Копирование в temp (non-ASCII)   │   │
│  │  2. cascadio.step_to_glb() / .load() │   │
│  │  3. (Опционально) gzip-сжатие        │   │
│  │  4. Отправка результата в очередь    │   │
│  └──────────────────────────────────────┘   │
└──────────────────────────────────────────────┘
```

### 1.2. Модульная структура

| Модуль | Назначение | Ответственность |
|--------|-----------|-----------------|
| `config.py` | Константы | Расширения, пресеты, пути, настройки по умолчанию |
| `utils.py` | Утилиты | Управление сессиями, I/O настроек, проверка кодировки путей |
| `worker.py` | Воркер | Фоновый процесс конвертации через cascadio |
| `widgets.py` | Виджеты | Кастомный виджет `Tooltip` для Tkinter |
| `app.py` | Приложение | GUI: окно, настройки, лог, прогресс |
| `main.py` | Точка входа | `freeze_support()`, очистка сессий, запуск `App` |

### 2.3. worker.py — Фоновый процесс

Функция `_worker()`:
- Принимает параметры конвертации через аргументы.
- Отправляет статусы и логи в GUI через `Queue`.
- Обрабатывает STEP через `cascadio.step_to_glb()`.
- Обрабатывает IGES через `cascadio.load()`.
- Опционально выполняет gzip-сжатие.
- Автоматически копирует файл во временную папку при non-ASCII путях.

**Протокол сообщений:**

| Тип | Ключи | Описание |
|-----|-------|----------|
| `log` | `text`, `tag` | Строка лога |
| `status` | `text` | Текущий статус |
| `tess_done` | `time`, `size` | Результат tessellation |
| `done` | `path`, `time`, `raw_mb`, `comp_mb` | Конвертация завершена |
| `error` | `text` | Ошибка |

## 3. Управление памятью

### 3.1. Временные файлы

- Каждый запуск создаёт уникальный каталог сессии: `%TEMP%/step2glb/<PID>/`.
- При non-ASCII путях входной файл копируется в каталог сессии.
- Промежуточный результат tessellation записывается в `output.glb` внутри каталога сессии.
- При завершении каталог сессии удаляется.

### 3.2. Очистка устаревших сессий

При запуске программы выполняется проверка `%TEMP%/step2glb/`:
- Если PID совпадает с текущим — каталог удаляется (остаток аварийного завершения).
- Если PID принадлежит несуществующему процессу — каталог удаляется.

### 3.3. Стратегия буфера

| Режим | Поведение |
|-------|-----------|
| `auto` | Если файл >500 МБ → временный файл на диске |
| `disk` | Всегда запись во временный файл |
| `none` | Всё в оперативной памяти |
| `force` | Всегда временный файл, независимо от размера |

## 4. Конвейер конвертации

### 4.1. STEP-файлы

```
Входной STEP → cascadio.step_to_glb() → GLB → [gzip] → Выходной файл
```

### 4.2. IGES-файлы

```
Входной IGES → чтение в bytes → cascadio.load(file_type="iges") → GLB bytes → запись → [gzip] → Выходной файл
```

### 4.3. Сжатие gzip

```
GLB (бинарный) → gzip.open() → по 1 МБ чанках → GLB.GZ
```

Размер сжатия: обычно 30–70% от исходного размера GLB.

---

## 5. Межпроцессное взаимодействие (IPC)

### 5.1. Механизм

Используется `multiprocessing.Queue` для передачи словарей-сообщений от воркера к GUI.

### 5.2. Потокобезопасность

- `Queue` — потокобезопасный объект из стандартной библиотеки Python.
- GUI опрашивает очередь через `after(100, ...)` — неблокирующий вызов.
- При пустой очереди исключение `Empty` подавляется через `try/except`.

### 5.3. Завершение воркера

- При закрытии окна с активной конвертацией: `proc.terminate()` + `proc.join(timeout=3)`.
- Воркеры создаются с `daemon=True` — автоматически завершаются при завершении основного процесса.

## 6. Обработка ошибок

| Ситуация | Поведение |
|----------|-----------|
| Неверное расширение файла | `messagebox.showerror` |
| Файл не найден | `messagebox.showerror` |
| Ошибка cascadio | Сообщение `error` в логе |
| Non-ASCII путь | Автокопирование + предупреждение в логе |
| Ошибка записи | Исключение ловится в worker, отправляется `error` |
| Конвертация при закрытии | Диалог подтверждения → terminate |

---

## 7. Безопасность

- Программа **не** использует сеть — все операции локальны.
- Программа **не** хранит и не передаёт секреты, ключи, токены.
- Все временные файлы удаляются при завершении.
- Пути к файлам не записываются в лог-файлы на постоянной основе.
- Код не содержит API-ключей и приватных данных.
